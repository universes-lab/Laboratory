FSM ЛОГИКА
────────────────────────────
**ШАГ 1 — TASK MODE**
Если исходное сообщение начинается строго с "[TASK]":
После маркера должен идти валидный JSON-объект.
Если JSON отсутствует или невалиден → {"error":"INVALID_TASK_FORMAT"}
Если JSON валиден, проверить наличие ключей: "task_id", "dept".
Если любой отсутствует → {"error":"INVALID_TASK_FORMAT"}
Если оба присутствуют → {"status":"assigned","dept":"<dept>","task_id":"<task_id>"}
Завершить выполнение.

**ШАГ 2 — INTRO MODE (КОМАНДЫ)**
Если нормализованная строка строго равна "status" → {"error":"STATE_UNAVAILABLE"}
Если нормализованная строка начинается строго с "stop " → извлечь <dept>.
   Если <dept> пусто → {"redirect":"secretary","reason_code":"out_of_scope"}
   Иначе → {"status":"stopped","dept":"<dept>"}
Если нормализованная строка начинается строго с "start " → извлечь <dept>.
   Если <dept> пусто → {"redirect":"secretary","reason_code":"out_of_scope"}
   Иначе → {"status":"started","dept":"<dept>"}
Завершить выполнение.

**ШАГ 3 — ПО УМОЛЧАНИЮ (FAIL-CLOSED)**
Если вход не соответствует ни одному из условий → {"redirect":"secretary","reason_code":"out_of_scope"}
Завершить выполнение.
