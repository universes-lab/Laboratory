## 2. Уточнение входа: ρ = 0

Навес с **ρ = 0** задаётся в координатах `rho-psi` непосредственно, как в К2. Об этом уже говорит § 2 версии 6: «при ρ = 0 угол ψ не определён — тогда перевод не выполняется, и навес задаётся напрямую в (ρ, ψ, δ)».
- Значения ψ при этом всё равно обязательно указывать (значений по умолчанию нет), но на построение ψ не влияет.
- Протокол печатает `psi_ignored: true`.
- П-5 действует: ρ = 0 точно.

Подменять ρ = 0 малым числом нельзя: тогда навес не поперечный, и тождества П-5 и П-8(г) могут не выполниться.

## 3. Новые правила свидетельств

### П-8(г). Касание навесов по симметрии переноса — `IMPOSED`

**Посылки** — всё по точным значениям входа и цепочкам тождеств:
1. **Соседние хозяева.** Навес H на торе нити h и навес H′ на торе h+1. Звено h зеркальное (δ = 0 точно) и θ_h = 0 точно; установлены П-2 и П-3. Тогда T_{h+1} = T_h, u_h = e_z(h) и A_{h+1} = A_h + 2·u_h — закрытая форма, d = 2.
2. **Одинаковые рамки узлов.** Из посылки 1: e_z(h+1) = u_h = e_z(h) и T_{h+1} = T_h, значит рамки узлов h и h+1 совпадают тождественно.
3. **Одинаковые навесы.** Сторона, система координат и параметры (ρ, ψ, δ) у H и H′ — одни и те же точные числа входа. Тогда e, d и ось навеса совпадают тождественно, и H′ = H + 2·u_h — перенос.
   - **Вариант с уравнением касания.** Свободный параметр у обоих навесов задан `fix` с перенесённым партнёром: у H — `with: T_{h−1}`, у H′ — `with: T_h`, одна вилка. Рамки узлов h−1, h и h+1 при этом совпадают по посылке 2. Корни совпадают как множества: уравнение переносится вместе с конфигурацией. Ядро берёт для обоих навесов одну вилку корня — оболочку двух — и строит обоих по ней.
4. **Ось навеса перпендикулярна переносу.** T_H ⊥ u_h установлено: П-5 (T_H = T_h, то есть δ_H = 0 и ρ = 0 или ψ ∈ {0°, 180°} точно) вместе с П-2 (u_h ⊥ T_h).

**Вывод.**
- Оси H и H′ равны, перенос 2·u_h перпендикулярен им, расстояние центров — 2.
- Значит, зазор рогатых торов равен 0 тождественно, касание боковое.
- Запись `contacts[]` для пары (H, H′):
  - `existence: IMPOSED`, `basis {rule: "П-8(г)", premises: […]}`;
  - `parallel: PARALLEL-ESTABLISHED` (правило П-6 — расширение ниже);
  - `type: SIDE` по построению;
  - `contact_class: "ALLOWED CONTACT"` — касание без общего кольца.

**Если выполнены посылки 1–3, но не 4,** перенос сохраняется, а касание — нет:
- оси H и H′ параллельны по построению (П-6);
- зазор считается по G-4: `SEPARATED` при вилке > 0, `CANDIDATE` при вилке, содержащей 0.

**Расширение П-6:** оси, равные по посылке 3 (тождественный перенос), — `PARALLEL-ESTABLISHED`.

**Что покрывается:**
- поперечная гребёнка (ρ = 0);
- равномерный сдвиг в плоскости нити (одинаковое ρ, ψ ∈ {0°, 180°}, δ = 0);
- лента при 30° — вариант с уравнением касания.

**Что не покрывается:** навесы через одного хозяина (перенос на 4·u — по G-4), навесы на разных сторонах, разные параметры, незеркальные или наклонные звенья. Там касание — только по G-4 и K-1.

### П-9. Параллельность плоскостей колец по построению

- **Посылка:** кольца RH и RH′ навесов из П-8(г), посылки 1–3. Тогда RH′ = RH + 2·u_h тождественно, нормали плоскостей равны.
- **Вывод — один из двух случаев:**
  - n·u_h = 0 тождественно — плоскости совпадают: случай `coplanar`, R-4;
  - n·u_h ≠ 0 — плоскости различны и параллельны: случай `parallel-distinct`, R-3. Расстояние между ними — 2·|n·u_h|, закрытая форма.

Без П-9 параллельность вилками не доказывается, и пара получает R-5, как в КТ-1.

## 5. B-1 — запрещённая конфигурация не выдаётся как допустимая

**Новый блок протокола `output`** — что ядро выдаёт как геометрию:

```
output: { geometry: "configuration" | null,
          admissible: true | false | null,
          violation: { check, req, objects, where, reason } | null,
          family: { … } | null }
```

| `verdict.geometry` | `output` |
|---|---|
| `PASSED` | `geometry: "configuration"`, `admissible: true` |
| `FORBIDDEN` | **`geometry: null`**, `admissible: false`, `violation` — первая нарушенная проверка с местом |
| `UNRESOLVED` | `geometry: null`, `admissible: null`, причина — в `unresolved` |

- Блок `configuration` у запрещённого случая остаётся: это запись того, что проверялось, для аудита. Геометрией инструмента он не является.
- Любой потребитель — сцены WP-6а, будущий HTML — берёт геометрию **только** из `output.geometry`.

**Семейство (новый вход § 4.4)** — для «последней допустимой конфигурации»:

```
"family": { "param": путь к параметру входа, "values": [v1, v2, …] }
```

- Ядро проверяет члены семейства по порядку и останавливается на первом с `FORBIDDEN` или `UNRESOLVED`.
- `output.family`:
  - `last_admissible` — значение и конфигурация последнего члена с `PASSED`;
  - `first_stop` — значение, вердикт и `violation` или причина;
  - члены после остановки не проверяются и не выдаются.
- Это **не путь**: между членами ничего не утверждается (TB-1, КТ-3).

**Б-7 проверяется свойством:** ни одна конфигурация в `output.geometry` и в `output.family.last_admissible` не имеет `FORBIDDEN`.
