## 4. Исправление исполнителя

**Диагноз.**
- 3489 ящиков `?` с причиной `sign ? at a0`, скопления у ρ ≈ 46,34° и 55,95°.
- Там корень d(ρ) проходит почти через узлы скана 1,66 и 1,74. В таком узле знак g(H1, T2) при точности 10⁻³ не определён.
- Скан всё равно ставил `prev_d` в этот узел. Поэтому левый конец начального отрезка оказывался точкой без доказанного знака.

**Правка** — `a5/solve_d.js`, полный скан, строки 97–98:

```diff
-    if (s !== '?') prev_sign = s;
-    prev_d = d;
+    if (s !== '?') { prev_sign = s; prev_d = d; }
```

**Почему это механика, а не метод:**
- `prev_sign` и до правки обновлялся только в узлах с доказанным знаком;
- правка лишь ставит `prev_d` туда же, то есть отрезок [prev_d, d] становится тем, что код и проверяет: концы с доказанными противоположными знаками;
- параметры, точности, геометрия и сертификация не тронуты.

Правило Автора: механический дефект исправляет исполнитель, пишет в журнал, сообщает DeepSeek. Здесь — журнал, запись 9.

**Сборка:** `solve_d.js` — `b4e1501e3c4a9e644f4adf9f1a1ceb1b89c64999b08d58285f2ab0e1333e5b8d`, архив — `82878d7c29163969931b14902b8eafd477cbb9e0e96b9ac77fff285c684c79ae`. Остальные 11 файлов совпадают с rev8.8 побайтно (опись).

**Проверено в коде, на чём держится строгость:**
- `check1_root.js`: ящик ρ, где `solveD` не сертифицировал d, получает `?` и уходит в W с `d_certified: false`; при слиянии ящиков в W вилка d — оболочка вилок всех ящиков;
