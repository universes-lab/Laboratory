**Найдено и исправлено при самопроверке:**
- **Предел процессов не действовал.** bubblewrap, запущенный от root, сопоставлял uid 65534 внутри с root снаружи, а для root ядро Linux `RLIMIT_NPROC` не применяет: при пределе 256 создались 406 процессов. ## 1. Устройство

**Папка прогона** — `/var/tmp/kt1-runs/<метка>-<время UTC>/`. Она лежит вне папок сессии: те закрыты 0700 для root, а nobody должен пройти к `src` и `work`. Владелец — root, права 0711: nobody может пройти, но не может читать список.

| Папка | Хозяин, права | В песочнице | Назначение |
|---|---|---|---|
| `src/` | root, 0444 / 0555 | `/sandbox/src`, только чтение, текущая папка | распакованный архив скрипта |
| `work/` | nobody, 0700 | `/sandbox/work`, запись (`KT1_OUT`, `HOME`) | всё, что пишет скрипт |
| `kernel/` | root, 0444 / 0555 | `/sandbox/kernel`, только чтение — **только d3-run** | замороженное ядро; `KT1_DIR=/sandbox/kernel/kt1` |
| `guard/` | root, 0444 / 0555 | `/sandbox/guard`, только чтение — только Python | копия `py_guard.py`, сумма — в журнале |
| `log/` | root, 0700 | **не монтируется** | доверенный журнал |

**Что ещё видно в песочнице:**
- `/usr` только для чтения, с ссылками `/bin`, `/lib`, `/lib64`;
- корень Node.js `/opt/node22` только для чтения — только для Node;
- свой `/proc` (своё пространство PID);
- минимальный `/dev` только для чтения;
- `/tmp` и `/dev/shm` в памяти, по 256 МиБ, стираются по выходе.

**Чего не видно:** `/etc`, `/home`, `/root`, `/var`, папок сессии, исходного архива ядра, журналов. Сети нет: в своём сетевом пространстве есть только loopback.

**Режимы:**

| Режим | Для чего | Ядро |
|---|---|---|
| `a5` | скрипты А-5, полностью | запрещено: `--kernel` → отказ; файлы ядра и вложенные архивы в архиве → отказ |
| `d3-selftest` | независимые модули Д-3 и их самопроверки, без `K.*` (разрешено Интегратором до фиксации) | запрещено, как в `a5` |
| `d3-check` | синтаксис каждого `.js` набора Д-3 (`node --check`) | запрещено, как в `a5` |
| `d3-run` | приёмочный прогон Д-3 | только архив с суммой `FROZEN_KERNEL_SHA`; архив набора по-прежнему не может содержать файлов ядра |

## 2. Порядок прогона

1. **Сумма архива** сверяется с суммой, которую зафиксировал Автор (`--sha`). Не совпала — отказ (код 2), запуска нет.
2. **Проверка архива до распаковки** (§ 0, п. 3). Любое нарушение — отказ (код 2) с причиной в журнале.
3. **Распаковка** в новую пустую `src/`, затем права только на чтение. Опись `src_before`: sha256 каждого файла.
4. **Только d3-run:** сумма архива ядра сравнивается с константой. Затем проверка, распаковка в `kernel/` и опись `kernel_before`.
5. **Запуск без изменений в песочнице** (§ 3). Слои:
   - внешний — bubblewrap от nobody плюс пределы;
   - Node — `--permission --allow-fs-read=/sandbox --allow-fs-write=/sandbox/work`;
   - Python — `py_guard.py` (audit hook: чтение — `/sandbox` и стандартная библиотека; запись — `/sandbox/work`; процессы, сокеты, `ctypes` запрещены).
6. **После прогона:** опись `src_after` и `src_unchanged`; для d3-run — `kernel_unchanged`. Также опись `work/` и её объём.
7. **Выходной архив** `<папка>-out.zip` (`log/` и `work/`) с sha256. Он передаётся без обработки.

## 3. Точная команда (пример из самопроверки, Python, режим a5)

```
setpriv --reuid=65534 --regid=65534 --clear-groups --no-new-privs --bounding-set=-all
  bwrap --unshare-all --die-with-parent --new-session --cap-drop ALL --clearenv
        --setenv PATH /opt/node22/bin:/usr/bin:/bin --setenv LANG C.UTF-8 --setenv HOME /sandbox/work
        --setenv KT1_OUT /sandbox/work --setenv KT1_RUN /sandbox --setenv KT1_READ /sandbox --setenv KT1_WRITE /sandbox/work
        --ro-bind /usr /usr --symlink usr/bin /bin --symlink usr/lib /lib --symlink usr/lib64 /lib64
        --proc /proc --dev /dev --size 268435456 --tmpfs /dev/shm --remount-ro /dev --size 268435456 --tmpfs /tmp
        --ro-bind <прогон>/src /sandbox/src --bind <прогон>/work /sandbox/work --ro-bind <прогон>/guard /sandbox/guard
        --remount-ro / --chdir /sandbox/src --uid 65534 --gid 65534
  prlimit --nproc=256 --nofile=512 --fsize=268435456 --cpu=1805 --as=8589934592 --
  timeout --kill-after=5 1800
  /usr/bin/python3.13 -I /sandbox/guard/py_guard.py a5/p.py
```

**Отличия для Node:**
- добавляется `--ro-bind /opt/node22 /opt/node22`, `guard` не монтируется;
- внутренняя команда — `node --permission --allow-fs-read=/sandbox --allow-fs-write=/sandbox/work <вход> [аргументы]`.

**Для d3-run** добавляются `--ro-bind <прогон>/kernel /sandbox/kernel` и `--setenv KT1_DIR /sandbox/kernel/kt1`.

**Пределы по умолчанию:**
- время — 1800 с по часам (`--timeout`), процессорное время — на 5 с больше;
- адресное пространство — 8 ГиБ на процесс (`--mem`);
- процессов — 256, дескрипторов — 512;
- файл — до 256 МиБ.

Пределы, отличные от умолчания, называются до прогона и попадают в журнал (`argv`).

## 5. Ограничения (в том числе замечания Грока)

- **audit hook в Python — не железная граница**, как и отметил Грок. C-расширения и обходные пути через уже загруженные модули его могут миновать. Поэтому граница — bubblewrap. Проба «Python, только bubblewrap» показывает, что без `py_guard` ядро всё равно не найдено, запись в исходники — EROFS, сеть — ENETUNREACH.
- **Дочерние процессы на внешнем слое разрешены.** Они остаются в тех же пространствах имён и под теми же пределами. Запрещает их только второй слой (`--permission`, `py_guard`). Это видно в пробах «только bubblewrap» (`child: ALLOWED`).
- **`scan.txt` из редакции 2 удалён.** Он был эвристикой; теперь ядро в режимах без ядра физически не смонтировано, а файлы ядра в архиве отвергаются по имени.
- **Флаг Node `--permission` в этой форме проверен на v22.22.0.** На другой версии самопроверку надо повторить до прогона.
- **Только LF.** `pack_from_text.py` отвергает текст с CR и не исправляет его.
- **Нет общего предела памяти и объёма `work/`.** cgroup в этом контейнере не делегированы. Действуют предел адресного пространства на процесс, число процессов, размер файла и объём `/tmp` и `/dev/shm`. Объём `work/` записывается (`work_bytes`).
- **`/etc` в песочнице нет.** Скрипт, которому нужны `/etc` (часовой пояс, пользователи, DNS), упадёт. Такая ошибка среды возвращается как есть. `TZ` не задан, время — UTC.
- **Сам запуск доверенный.** Он работает от root снаружи песочницы, в одноразовом облачном контейнере сессии. Чужой код выполняется только внутри песочницы от nobody.

## 6. Что нужно от скриптов, чтобы их не править

- **Один архив (`.zip`)** и одна строка запуска: язык, входной файл, аргументы. Ты называешь их при сдаче. Пути в архиве — из символов `[A-Za-z0-9._-]` и `/`.
- **Только встроенные модули Node.js или стандартная библиотека Python 3.13.** Внешних пакетов, сети и запуска процессов нет.
- **Чтение** — только своих файлов, относительно своей папки. Текущая папка — корень архива.
- **Вывод** — в stdout / stderr или в файлы в папке `KT1_OUT` (Node: `process.env.KT1_OUT`; Python: `os.environ['KT1_OUT']`). Писать в другие места нельзя.
- **Д-3 — путь к ядру только через `KT1_DIR`:**
  - `KT1_DIR` — папка, где лежит `kt1.js`;
  - подключение: `require(path.join(process.env.KT1_DIR, 'kt1'))`;
  - зашитых путей быть не должно, файлов ядра в архиве набора — тоже.
- **А-5 — ядро не упоминается вовсе.** Оно не смонтировано, а файлы с именами ядра в архиве отвергаются.

## 7. Формат сдачи текстом (для упаковки)

Каждый файл — заголовок и сразу за ним блок кода:

    ### FILE: a5/check1_root.js
    ```js
    …содержимое файла…
    ```

- **Путь** — относительный, из сегментов `[A-Za-z0-9._-]`; без `.`, `..`, пустых сегментов, `\` и ведущего `/`; не длиннее 200 символов. Дубликаты без учёта регистра отвергаются.
- **Содержимое блока пишется в файл дословно**, с переводом строки в конце. Если внутри файла есть тройные обратные кавычки, ограждай блок четырьмя.
- **Только LF.** Текст с CR отвергается целиком.
- **Сборка** — `pack_from_text.py`:
  - порядок файлов — по пути, время фиксированное, без сжатия;
  - после сборки архив перечитывается и сверяется с текстом побайтно;
  - печатается опись: sha256 исходного текста, каждого файла и архива.
- **Воспроизводимость:** тот же текст дважды даёт один и тот же архив, проверено.
- **Автор сверяет** опись и архив с твоим опубликованным текстом и фиксирует сумму от своего имени.
- **Раздельно:** А-5 и Д-3 — два отдельных текста и два архива.
