## 3. Второй дефект — `sinI` уходит в бесконечную рекурсию

Твою библиотеку я запустил отдельно, без изменений кода:

```
N=180: сбоев нет
N=360: сбой в узлах j = 45, 135, 225, 315   (φ = 45°, 135°, 225°, 315°)
RangeError: Maximum call stack size exceeded   at sinI (lib/ia.js:136)
```

**Причина.** Узкая вилка φ лежит на границе секторов kπ/2 ± π/4: `Math.round` даёт её концам разные k. Ты делишь вилку пополам. Но если концы — соседние числа double, середина совпадает с одним из концов, и снова получается та же вилка.

**Следствие.** Любой вызов `gapTorusTorus`, которому мало N = 180, удваивает N до 360 и падает. **Ни один зазор сейчас не считается.**

## 4. Точность — калибровка не пройдёт и после исправления §§ 2–3

**4.1. Ширина вилки зазора.** Она ≈ π/N плюс ширина вилок в узлах: поправка L·h/2 прибавляется к обеим границам.
- `N_max: 65536` из README до функции не доходит: `check1_root` передаёт только `tol`. Значит, действует умолчание 4096.
- В `solve_d.js` `tol` зашит — 10⁻³.
- При N = 4096 ширина ≈ 7,7·10⁻⁴, при 65536 ≈ 4,8·10⁻⁵.

**4.2. К3 — аналитически, по твоему README, § 1.4:**
- A_H1 = (2cos ρ, 0, 4 − 2sin ρ), оси параллельны, отсюда **g(ρ) = √(8 − 8 sin ρ) − 2**;
- наклон в корне |dg/dρ| = √3 на радиан ≈ **0,0302 на градус**;
- ширина W ≈ (ширина вилки зазора) / 0,0302: при N = 4096 это ≈ 0,025°, при 65536 ≈ 0,0016°;
- **оба значения больше 0,001°.**

**4.3. К4 — по твоим выходам rev7:**
- у К4 наклон ≈ **0,0086 на градус**: `gap_hi` меняется на 0,0043 за 0,5°;
- чтобы W легла в окно [57,260°; 57,262°] шириной 0,002°, ширина вилки зазора у корня нужна **≲ 1·10⁻⁵**, с запасом.

**4.4. Два замечания по существу:**
- верхней границе минимума поправка Липшица не нужна: значение в узле достигается, поэтому min ≤ min_j d.hi. Это вдвое сужает вилку;
- равномерное удвоение N — не адаптивное деление:
  - замерил — ≈ 39 мкс на узел φ, при N_max = 65536 это ≈ 5 с на вызов;
  - `solveD` делает до ~56 вызовов на ящик ρ;
  - спецификация G-4 требует «глобальный минимум — ветвями и границами»: дробить только там, где нижняя граница ниже лучшей верхней;
  - **метод — твоя зона.** Требование одно: объявленная `gap_tol` действительно достигается, иначе `?`. И прогон укладывается в 1800 с.
