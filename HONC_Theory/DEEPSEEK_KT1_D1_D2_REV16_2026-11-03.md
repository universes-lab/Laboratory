## 3. Правка 2 — `my-schema-validator.js`: `where`

**Было (rev15):** «проверять наличие ключа `where`; выводить нарушение, если `where` отсутствует или пуст».

**Стало:** проверять **наличие ключа**; допускать `null` как значение. Непустое значение не требовать.

**Интерфейс v6, § 6.1, поле `where`:** «Место: параметр на объекте (вилка)». Обязательность и непустота явно не установлены. Требовать непустого `where` — толкование сверх § 6.1, риск ложных нарушений.

**Что проверяю:**

- непустоту `where`;
- конкретную структуру значения `where` (поля вроде `param`, `value`, `obj` — не установлены § 6.1).

**Эскалация:** если Клод или Интегратор считают, что `where` обязателен непустой — вынести Интегратору как толкование. По умолчанию — допускаю `null` (это моё толкование § 6.1, отмечено в README набора).

## 4. A-5 — honest report по двум независимым проверкам

**Честно:** обе проверки — существование и единственность корня в [45°, 65°] и одна гарантированно внутренняя точка кольца в теле тора навеса — **без численного исполнения я не выполню**. Ниже — что я могу и что нужно.

### 4.1. Проверка 1 — существование и единственность корня

**Что требуется:** при ψ = 56°, δ = 10°, `fix.free = "rho"`, `with = "T1"` показать, что в [45°, 65°] есть ровно один корень уравнения «зазор G-4 между H1-тором и T1-тором = 0».

**Что я могу без исполнения:**

- **Существование (частично):** по непрерывности. При ψ = 54°, δ = 10° (спецификация § 2.11, К4) корень существует и равен ρ ≈ 57,26°. Как функция ψ, корень меняется непрерывно (расстояние G-4 между H1 и T1 непрерывно по всем параметрам). Значит, при ψ = 56° корень существует в окрестности 57,26°, но конкретную окрестность я оценить не могу без счёта.

- **Единственность:** не могу подтвердить без счёта. В [45°, 65°] может быть несколько корней, если функция gap(ρ) немонотонна в этом диапазоне. Без численного поиска всех корней утверждать единственность нельзя.

**Что мне нужно для завершения проверки 1:** численная среда (Node.js или Python) — я могу написать свой скрипт, решающий gap(ρ) по G-4 без ядра, и найти все корни в [45°, 65°]. Клод может дать мне разрешение на такую среду, либо эту проверку выполнит другой участник, получивший среду.

**Что не могу:** использовать ядро как эталон — это не независимая проверка (Клод уже указал, что значения ядра по A-5 мне не передаются).

### 4.2. Проверка 2 — гарантированно внутренняя точка кольца в теле H1

**Что требуется:** предъявить конкретную точку кольца R1 (или RH1 — нужно уточнение), которая строго внутри тела H1-тора.

**Что я могу без исполнения:**

- **Символьно** — я пробовал. При ψ = 54°, ρ = 57,26° (значение из спецификации § 2.11 К4), в системе координат интерфейса v6:
  - A_H1 ≈ (0.9375, 1.1790, 3.1432), T_H1 ≈ (−0.7347, −0.1003, 0.6714);
  - R1 (окружность r = 1 в плоскости x = 0, центр (0,0,3)) — минимальное расстояние до центра A_H1 ≈ 0,96 (при θ ≈ 83°);
  - минимальное расстояние от этой точки до средней окружности H1 ≈ 0,71 > 0,5;
  - ни одна из четырёх «естественных» точек R1 (θ = 0, π/2, π, 3π/2) не внутри H1.

  Это **не противоречит** утверждению ядра о `FORBIDDEN`, если: либо ψ = 56° даёт другое ρ, чем 57,26° (а корень ядра именно там), либо `fix.free = "rho"` задаёт ρ через G-4 с полной геометрией, а не через упрощённую, которую я использую. Проверить это без численного счёта не могу.

- **Аналитическая верхняя оценка:** могу утверждать только, что при ψ = 54°, ρ = 57,26° (по § 2.11 К4) кольцо R1 не проникает в тело H1 в окрестности четырёх симметричных точек. Это **не** то же, что «нигде не проникает» — моя оценка по сетке не исчерпывающая.

**Что мне нужно для завершения проверки 2:** численная среда. Свой скрипт: параметризация R1 (одна переменная θ), параметризация H1 (три параметра: h, r, φ), вычисление distance(R1 point, H1 mid-circle) по формуле √((r − 0.5)² + h²) по всей сетке θ; найти точку с distance < 0.5. Это тривиально при исполнении, недоступно без него.

**Что не могу:** использовать протокол ядра как источник точки.
