## 1. Единицы и соглашения

- **Длины** — в единицах R, где длина кольца 2πR, то есть R = 1. Тор: a = b = ½.
- **Углы на входе и в протоколе** — в градусах, десятичной записью.
- **Координаты** — правая тройка (x, y, z).
- **Вилка** — пара чисел `[lo, hi]` с lo ≤ hi. Каждое число — точное двоичное значение с плавающей точкой, записанное в JSON без потери (кратчайшая точная запись). Вилка гарантированно содержит истинное значение — если полнота `EXACT` или `CERTIFIED`.
- **Вектор-вилка** — три вилки.

## 2. Построение (G-7): точные определения

Каждый Qf — тор со своим кольцом. Кольцо тора k продевает тор k и следующий тор нити. Кольцо последнего тора свободно: строится тем же правилом звена, но в его второй точке тора нет.

**Начало.** Тор T0: центр A₀ = (0, 0, 0), ось T₀ = +ŷ; начальное направление нити e_z = +ẑ.

**Рамка узла k** — для тора k с осью T_k и входящим направлением e_z (направление звена, пришедшего в тор k; для k = 0 — +ẑ):
- e_y = нормированная часть T_k, перпендикулярная e_z. Если она вырождена — e_y = нормировка (e_z × x̂);
- e_x = e_y × e_z.

**Звено k** из тора k, параметры (θ, φ, δ):
- направление: u = e_z·cos θ + (e_x·cos φ + e_y·sin φ)·sin θ;
- зеркальная ось: T′ = T_k − 2(T_k·u)·u;
- ось следующего тора: T_{k+1} = поворот T′ на угол δ вокруг n = нормировка(u × T_k), по правилу правой руки;
- δ = 0 — зеркальное звено;
- расстояние d:
  - зеркальное звено: d = 2(½·√(1 − (T_k·u)²) + ½);
  - незеркальное: d — корень уравнения «зазор G-4 = 0» вдоль u, с вилкой и проверкой единственности;
- центр следующего тора: A_{k+1} = A_k + d·u;
- кольцо k — плоский эллипс длины 2π через A_k и A_{k+1}, касательный к T_k в A_k и к T_{k+1} в A_{k+1} (G-2). Как кольцо записывается в протоколе и с какой точностью — § 6.5;
- последнее звено строится по тому же правилу с явно заданными (θ, φ, δ). Его кольцо свободно: тора в точке A_n нет;
- **зеркальное звено** (δ = 0) — конвенция модели [Г] (Раунд 3а, § 1). Ядро её не подставляет: δ всегда приходит из входа, а протокол помечает каждое зеркальное звено (§ 6, `conventions`).

**Навес** — на торе-хозяине h нити, сторона s ∈ {+1, −1}, рамка узла h:
- в координатах (ρ, ψ, δ): e = s·e_x·cos ρ + (−e_z·cos ψ + e_y·sin ψ)·sin ρ.
  - ρ — отклонение от поперечного направления s·e_x.
  - ψ = 0 — отклонение назад, к предыдущему тору (−e_z); ψ = 180° — вперёд; ψ = 90° — вдоль оси хозяина.
- в координатах сцены захвата (α, λ, δ): e = cos λ·(s·cos α·e_x + sin α·e_y) − sin λ·e_z.
  - α — азимут от экватора хозяина к его оси; λ — отклонение назад.
  - Перевод: cos ρ = cos λ·cos α; ψ = atan2(cos λ·sin α, sin λ). При ρ = 0 угол ψ не определён — тогда перевод не выполняется, и навес задаётся напрямую в (ρ, ψ, δ).
- тор навеса и его кольцо строятся по правилу звена из хозяина с u = e и данным δ.

  Кольцо навеса продевает навес и хозяина.

**Имена объектов:**
- торы нити — `T0`…`T{n−1}`; навесы — `H1`, `H2`, …;
- кольцо тора нити k — `R{k}`; кольцо навеса j — `RH{j}`.

**Ориентация осей.** Ось T каждого тора — ровно тот вектор, который дало построение. Знак J5 на отдельном ребре, sign(v_A·v_B) с v = T × (c − A), зависит от этой ориентации. Произведение знаков по циклу и итоги K-6 от неё не зависят.

## 3. Свидетельства построения: правила (П-1…П-8)

Ядро выводит свидетельства только по этим правилам. Каждое свидетельство в протоколе указывает своё правило и посылки. Численная близость свидетельством не является.

| Правило | Свидетельство | Когда |
|---|---|---|
| П-1 | T₀ ⊥ e_z (тождество) | Начало нити |
| П-2 | u ⊥ T_k (тождество) | T_k ⊥ e_z установлено и θ = 0 или φ ∈ {0°, 180°} — точные значения входа |
| П-3 | T_{k+1} = T_k (тождество) | Звено зеркальное (δ = 0 точно) и u ⊥ T_k установлено. Тогда отражение оставляет ось неизменной |
| П-4 | T_{k+1} ⊥ e_z следующего узла | Из П-3: новое e_z = u, а u ⊥ T_k = T_{k+1} |
| П-5 | T_навеса = T_хозяина (тождество) | δ = 0 точно и e ⊥ T_хозяина установлено: ρ = 0 или ψ ∈ {0°, 180°} точно, при T_хозяина ⊥ e_z хозяина |
| П-6 | `PARALLEL-ESTABLISHED` для пары | Оси пары равны или противоположны по цепочке тождеств П-3, П-5 или по явному объявлению входа (§ 4.3) |
| П-7 | Касание боковое по построению | Пара из П-6, и разность центров перпендикулярна оси по цепочке тождеств: все звенья между ними имеют u ⊥ T, установленное по П-2 или П-5 |
| П-8 | `IMPOSED` | (а) Сцепленная пара — звено с d из закрытой формы или доказанного корня. (б) Конфигурация задана уравнением касания (§ 4.2), корень доказан и единствен в вилке. (в) Явное объявление симметрии во входе — только в синтетических случаях, с записью основания |

**Торцевое касание** в базовых случаях КТ-1 по построению не возникает. Торцевой тип устанавливается только явным синтетическим объявлением (§ 4.3).

**Если свидетельства нет:**
- **параллельность** классифицируется по сертифицированной вилке abs(T_A × T_B):
  - вилка отделена от нуля — `NON-PARALLEL`;
  - иначе — `PARALLEL-UNCERTAIN`, даже если вилка равна [0, 0];
- **тип касания:**
  - вилка abs(n·T) у обоих торов отделена и от 0, и от 1 — сертифицированно смешанный тип;
  - иначе тип не установлен.

## 4. Вход: описание случая (JSON)

### 4.1. Конфигурация нити с навесами

```json
{
  "id": "K4",
  "thread": { "n": 5, "links": [
    { "theta": 0, "phi": 0, "delta": 0 }, { "theta": 0, "phi": 0, "delta": 0 },
    { "theta": 0, "phi": 0, "delta": 0 }, { "theta": 0, "phi": 0, "delta": 0 },
    { "theta": 0, "phi": 0, "delta": 0 } ] },
  "hangs": [
    { "host": 2, "side": 1,
      "coords": "rho-psi", "rho": null, "psi": 54, "delta": 10,
      "fix": { "kind": "contact", "free": "rho", "with": "T1", "bracket": [57.0, 57.5] } }
  ]
}
```

- `thread.n` — число торов нити.
- `thread.links` — ровно n записей (θ, φ, δ) для звеньев 0…n−1, включая последнее, со свободным кольцом.
- `hangs[]` — навесы:
  - `coords`: `"rho-psi"` или `"alpha-lambda"`;
  - параметры `rho`, `psi`, `delta` или `alpha`, `lambda`, `delta`.
- **Значений по умолчанию нет.** Отсутствующий параметр — `input_error`. Исключение — свободный параметр уравнения касания: он равен `null` (§ 4.2).
- Числа входа понимаются как точные десятичные значения. Ядро заключает их перевод в радианы в вилку.

### 4.2. Конфигурация, заданная уравнением касания

Поле `fix` задаёт один параметр навеса уравнением «зазор G-4 между навесом и тором `with` равен нулю»:
- `free` — свободный параметр: `rho`, `psi`, `lambda` или `alpha`; во входе он равен `null`;
- `bracket` — вилка поиска корня, в градусах.

**Обязательства ядра:**
- доказать существование и единственность корня в вилке. Не удалось — конфигурация не строится, протокол содержит `UNRESOLVED` с причиной;
- касание с `with` получает `IMPOSED` по П-8(б); основание: уравнение, вилка, вилка корня, способ доказательства единственности;
- все остальные проверки выполнить на всей вилке корня, а не в её середине.

**Ограничение.** «Первое касание вдоль пути» этим не удостоверяется: доказывается лишь, что корень в вилке единствен. Нет ли касания раньше, по параметру пути, — вопрос пути (TB-1), в КТ-1 не решается.

**Без `fix`** все параметры берутся как числа. Касание с зазором, вилка которого содержит 0, тогда получает `CANDIDATE` (K-1). Так задаётся испытание Б-8.

### 4.3. Синтетические объекты

Для испытаний вне построения нити:

```json
{
  "id": "B10-like",
  "tori": [
    { "name": "S1", "A": [0, 0, 0], "T": [0, 1, 0] },
    { "name": "S2", "A": [2, 0, 0], "T": [1e-15, 1, 0] },
    { "name": "S3", "A": [0, 0, 2], "T": { "sameAs": "S1" } }
  ],
  "rings": [
    { "name": "Q1", "C": [1, 0, 0], "E1": [1, 0, 0], "E2": [0, 1, 0], "s1": 1, "s2": 1,
      "threads": ["S1", "S2"] }
  ],
  "declare": [ { "kind": "symmetry", "pair": ["S1", "S3"], "contact": "IMPOSED", "basis": "text" } ]
}
```

- **Тор:** центр `A`, ось `T` — числа или `{ "sameAs": имя }` / `{ "oppositeOf": имя }`. Ссылка — явное тождество (П-6). Числовая ось тождеством не является, даже если совпадает с другой поразрядно. Числовую ось ядро нормирует; результат нормировки — вилка.
- **Ортонормированность** `E1`, `E2` ядро проверяет по вилкам. Не подтверждена — `input_error`.
- **Кольцо:** центр `C`, ортонормированные `E1`, `E2`, полуоси `s1`, `s2`; эллипс C + s1·cos t·E1 + s2·sin t·E2.
  - `threads` — какие торы оно продевает. Это **объявление входа**: построением оно не выводится.
    - Ядро проверяет его на совместимость: вилки невязок должны содержать 0. Невязки — прохождение кольца через центр тора, касание оси, ось в плоскости кольца.
    - Если хотя бы одна вилка отделена от нуля — `input_error`.
    - Совместимость — не сертификат. В протоколе она записывается как посылка входа, и проверка «кольцо против продетого тора» (G-5б–г) идёт при этой посылке.
- **`declare`** — явные объявления. Допустимы ровно два вида:
  - `{ "kind": "symmetry", "pair": [A, B], "contact": "IMPOSED", "basis": текст }` — П-8(в);
  - `{ "kind": "type", "pair": [A, B], "type": "SIDE" | "AXIAL", "basis": текст }` — тип по объявлению.

  Любой другой вид — `input_error`. В протоколе объявления помечаются как объявления входа.
- **Без объявления типа** тип синтетической пары не установлен. Ядро может лишь сертифицировать смешанный тип (§ 3).
- Синтетические кольца не обязаны иметь длину 2π: ядро проверяет длину только у колец, построенных по § 2.
- Синтетическое кольцо попадает в протокол записью § 6.5 с `source: "synthetic"`. Его вилки — перевод чисел входа, и ширины печатаются так же.

## 5. Консольный вход

```
node kt1.js случай.json > протокол.json
```

**Коды выхода:**
- 0 — протокол выдан, при любом вердикте;
- 2 — вход отвергнут как неправильный: протокол содержит `input_error` и не содержит вердиктов;
- 3 — внутренняя ошибка ядра: протокол содержит `kernel_error`; никакого вердикта.

Ядро не читает ничего, кроме файла случая. Прогон детерминирован: тот же вход даёт побитно тот же протокол.

## 6. Выход: протокол (ИФ-4)

```json
{
  "protocol": "honc-qf-r1-kt1", "interface": 5, "kernel": { "version": "…" },
  "case": { "…": "эхо входа" },
  "declared": { "kappa_min": …, "theta_min_deg": …, "n_max_candidates": 8,
                "bnb_max_evaluations": …, "root_max_iterations": …, "k2_display_thresholds": [0.05, 0.95] },
  "configuration": { "tori": […], "rings": […], "evidence": […],
                     "conventions": [ { "link": "R0", "mirror": true, "status": "[Г] конвенция модели, Раунд 3а § 1" } ] },
  "checks": […],
  "contacts": […],
  "j5": { "edges": […], "canon": {…}, "ext": {…}, "ysigns": […], "branches": […] },
  "verdict": { "geometry": "PASSED|FORBIDDEN|UNRESOLVED", "rule": "spec §1" },
  "unresolved": […],
  "registry": "registry_S3.json"
}
```

### 6.1. Запись проверки (`checks[]`)

| Поле | Значение |
|---|---|
| `id` | Уникальное имя проверки |
| `req` | ID требования спецификации: `G-4`, `G-5а`, `G-5в`, `R-1`… |
| `objects` | Имена объектов |
| `quantity` | Что измерено: `gap`, `margin`, `kappa_r`, `kappa_margin`, `halfplane_angle`, `length_residual`… |
| `value` | Вилка |
| `completeness` | `EXACT` / `CERTIFIED` / `SAMPLED` / `UNRESOLVED` |
| `verdict` | `PASSED` / `FORBIDDEN` / `UNRESOLVED` |
| `reason` | Обязательно при `FORBIDDEN` (ограничение и место) и при `UNRESOLVED` (причина) |
| `where` | Место: параметр на объекте (вилка) |
| `level` | `L1` — найдено · `L2` — проникновений не обнаружено · `L3` — согласовано по J5. `L4` в КТ-1 не выдаётся, `L5` не выдаётся никогда |
| `layer` | `CARRIER` (в КТ-1 других слоёв нет) |
| `status` | Ссылка на строку реестра или `null` |

**Инвариант схемы:** запись с `verdict = PASSED` и `completeness`, отличной от `EXACT` и `CERTIFIED`, недопустима. Ядро такую запись не выпускает; валидатор обязан её отвергать.

### 6.2. Запись касания 2D–2D (`contacts[]`)

| Поле | Значение |
|---|---|
| `pair` | Два тора |
| `existence` | `IMPOSED` / `CANDIDATE` / `SEPARATED` / `PENETRATION` |
| `basis` | Для `IMPOSED`: правило П-8 и его данные (уравнение, вилка, вилка корня, способ доказательства единственности; или объявление) |
| `gap` | Вилка зазора |
| `points` | Вилки точек касания c, нормалей n, abs(n·T_A), abs(n·T_B), косинуса — для каждой точки множества касания |
| `parallel` | `PARALLEL-ESTABLISHED` (с правилом) / `PARALLEL-UNCERTAIN` / `NON-PARALLEL` (с вилкой abs(T_A × T_B)) |
| `type` | `SIDE` / `AXIAL` — только по построению или объявлению, с правилом · `MIXED` — сертифицированно · `UNDETERMINED` |
| `type_display` | Тип по порогам K-2 — только для показа, на чтение не влияет |
| `reading` | `J5-CANON` / `J5-EXT` / `J5-DEGENERATE` / `J5-CLASS-UNRESOLVED` |
| `sign` | +1 / −1 / `null`. `null` — при `J5-DEGENERATE` и при разных знаках в разных точках (K-5) |
| `epsilon` | Полуширина сертифицированной вилки косинуса (K-4); при нескольких точках — наибольшая из полуширин по точкам. Вырождение — вилка косинуса содержит 0 хотя бы в одной точке |
| `contact_class` | `STRUCTURAL` — сцепленная пара · `ALLOWED CONTACT` — касание `IMPOSED` без общего кольца · `UNRESOLVED CONTACT` — при `CANDIDATE` и при K-5 |

### 6.3. Запись J5 (`j5`)

- `edges[]`: пара, класс (`LINK` / `CONTACT-ONLY`), `reading`, `sign`, `on_cycle`, `bridge`.
- `canon`:
  - `verdict` — `PASSED` / `FORBIDDEN` / `UNRESOLVED`;
  - `reason`;
  - `inconsistent_canon_cycle` — цикл, если найден;
  - `non_canon_edges`;
  - `uncovered_bridges`.
- `ext`: `verdict` — `PASSED-EXT` / `FORBIDDEN-EXT` / `UNRESOLVED`; `label` — всегда `"[Г, мост]"`; `reason`.
- `ysigns[]`: тор; знак относительно его оси T; `label` — `CANON` или `"[Г, мост]"`. Затравка — первый тор, знак +1; это условность.
- `branches[]` — при кандидатах (K-1): допущение «есть / нет касания» для каждого кандидата, итоги каждой ветви; общий итог `UNRESOLVED`, если ветви расходятся.

  Кандидатов больше `n_max_candidates` — итог `UNRESOLVED` с этой причиной.

### 6.4. Запись пары колец

Пара колец — запись в `checks[]` с `req` из R-1…R-6 и полями:
- `case`: `shared-cusp` / `nonparallel` / `parallel-distinct` / `coplanar` / `near-parallel` / `relation-undetermined`;
- `halfplane_angles` (для R-1);
- `chords`, `indicators` (π, ρ), `lk` (для R-2);
- `separating_direction` (для R-4);
- `meeting` (для R-6).
- `contact_class`: `STRUCTURAL` · `UNRESOLVED CONTACT` при статической встрече · `DEGENERATE MEETING`.

`ALLOWED CONTACT` и `FORBIDDEN CROSSING` для колец в КТ-1 не выдаются: это классы событий на пути (R-2).

### 6.5. Запись кольца (`configuration.rings[]`) — добавлено в версии 5

| Поле | Значение |
|---|---|
| `name` | `R{k}`, `RH{j}` (§ 2) или имя синтетического кольца (§ 4.3) |
| `source` | `construction` — построено по § 2 · `synthetic` — задано входом (§ 4.3) |
| `owner` | Тор, чьё это кольцо; у синтетического — `null` |
| `threads` | Какие торы кольцо продевает. У построенного — по построению; у синтетического — объявление входа (§ 4.3) |
| `free` | `true` — кольцо последнего тора нити: во второй точке тора нет |
| `C`, `E1`, `E2` | Вектор-вилки центра и главных осей |
| `s1`, `s2` | Вилки полуосей вдоль `E1` и `E2` |
| `annulus` | `false` — при каждом t вилка C + s1·cos t·E1 + s2·sin t·E2 содержит точку кольца с этим t. `true` — ориентация осей в плоскости кольца не установлена. Тогда кольцо лежит в плоской кольцевой области вокруг C в плоскости (`E1`, `E2`): расстояние до C — в вилке `s1` = `s2`. Точки кольца по t в этом случае не сопоставляются |
| `length` | Вилка длины. Только у построенного кольца; у синтетического — `null` |
| `residual` | Вилка `length − 2π`. Только у построенного кольца; у синтетического — `null` |
| `completeness` | `EXACT` — кольцо по тождеству (окружность радиуса 1, § 2) или синтетическое из точно представимых чисел · `CERTIFIED` — во всех остальных случаях |
| `basis` | Основание: тождество; корень уравнения длины и довод его единственности; вход |
| `widths` | Ширины вилок: `C`, `E1`, `E2` (наибольшая по трём компонентам), `s1`, `s2`, `length`, `residual`. Каждая ширина — верхняя оценка hi − lo с округлением вверх; у вилки из одного числа — 0; у отсутствующего поля — `null` |
| `width_max` | Наибольшая из `widths` по полям `C`, `E1`, `E2`, `s1`, `s2` — ширина вилки положения кольца |

**Ширины выводятся у каждого кольца**, в том числе нулевые. Запись кольца без `widths` — нарушение схемы; `K.validate` её отвергает.

`EXACT` не означает нулевых ширин. Например, центр кольца по тождеству — сумма вилок, а сумма округляется наружу. Поэтому его вилка шире нуля на несколько единиц последнего разряда.

**Правило полной вилки (поправка G-2).**
- Каждая проверка, в которой участвует кольцо (G-5а–г, R-1…R-6), вычисляется на полных вилках полей кольца — не в серединах и не на «номинальном» эллипсе.
- При `annulus: true` проверка использует кольцевую область целиком.
- Если на полных вилках проверка не даёт доказанного `PASSED` или `FORBIDDEN`, её итог — `UNRESOLVED`. Причина в `reason` — `ring-enclosure`, с именем кольца и `width_max`.

**Точность.**
- Не хуже 10⁻¹² — только у d (G-3), у `K.perimeter` при точных полуосях и у колец по тождеству.
- У кольца общего вида верхней границы ширины нет. Ширина печатается, и последующие проверки её учитывают по правилу выше.
- Требования к сертификату К4 прежние (§ 8).

## 7. Библиотечные точки

Для испытаний WP-0, K-6 и изолированных проверок: `const K = require('./kt1')`. Каждая точка возвращает фрагмент протокола той же схемы.

| Точка | Вход | Выход | Нужна для |
|---|---|---|---|
| `K.perimeter(s1, s2)` | Полуоси — числа или вилки | Вилка периметра эллипса, полнота. При точных полуосях ширина не больше 10⁻¹² (G-2) | м1 |
| `K.minimize({ f, a, b, L, periodic })` | `f(x)` → вилка значения в точке x; предоставляешь ты, со своей оценкой; L — константа Липшица | Вилка минимума, вилки точек минимума, полнота | м3, WP-0 |
| `K.root({ F, dF, a, b })` | `F(lo, hi)` и `dF(lo, hi)` — вилки функции и производной на отрезке | Вилка корня, `unique: true/false`, полнота | WP-0 |
| `K.run(case)` | Описание случая (§ 4) — объект, а не файл | Полный протокол (§ 6), побитно тот же, что выдаёт консоль. При неправильном входе — протокол с `input_error` | Весь набор: чёрный ящик без запуска процесса |
| `K.build(case)` | Описание случая (§ 4) | `configuration` со свидетельствами | WP-1: невязки, тождества |
| `K.torusGap(t1, t2)` | Торы `{A, T}` | Вилка зазора, вилки минимумов, полнота | G-4 |
| `K.ringTorus(ring, torus, threaded)` | Кольцо — по § 4.3 (числа) или записью § 6.5 (вилки); тор; продевает ли | Проверка G-5а или G-5б–г с κ_r, запасом, r₀ | м2б, Кλ3 |
| `K.ringRing(r1, r2, sharedCusp)` | Два кольца — по § 4.3 или записью § 6.5; общий касп `{A, T}` или `null` | Запись пары колец (§ 6.4) — без тел | м2а |
| `K.j5Reading({ parallel, type, cos })` | `parallel`: `PARALLEL-ESTABLISHED` / `PARALLEL-UNCERTAIN` / `NON-PARALLEL`. `type`: `SIDE` / `AXIAL` (установленные), `MIXED` (сертифицированный), `UNDETERMINED`. `cos` — список вилок `[lo, hi]` по точкам касания | `reading` — по K-3 из `parallel` и `type`; `sign` (`null` при вырождении или при разных знаках); `epsilon` (§ 6.2: при нескольких точках — наибольшая полуширина); `contact_class` (`UNRESOLVED CONTACT` при разных знаках, K-5) | K-3…K-5, Б-5 |
| `K.j5Graph({ vertices, edges })` | Рёбра: `{a, b, cls, existence, reading, sign}` | Запись `j5` (§ 6.3) | K-6, Б-8, Б-9, твой перебор раскрасок |
| `K.validate(protocol)` | Протокол | Список нарушений схемы | Инварианты § 6.1 и § 6.5 |

Функции `f`, `F`, `dF` вызываются только с числами и вилками и ничего не возвращают, кроме вилок. Ядро не исследует их устройство.
