## 5. Требования к синтетическому провайдеру (fixture) — требования, не проект
### 5.1 Свойства [MUST]
- Только локальный loopback; исходящих соединений нет; не имитирует чей-либо бренд, интерфейс и логотипы.
- Форма входа и сессионная cookie с управляемым сроком жизни; принудительный logout и «challenge» (страница подтверждения) включаются переключателем.
- Постоянный адрес беседы с идентификатором `conv_id`; несколько бесед.
- Заранее заданная «затравка»: известная начальная история (счётчики, тексты, роли).
- Ответ ассистента формируется детерминированно, с управляемой задержкой и признаком завершения; потоковая выдача.
- Ленивая подгрузка длинной истории (неполная загрузка до прокрутки), чтобы `history_complete` было содержательным.
- Переключатели: потеря сессии, конфликт двойного владения (две вкладки на беседу), смена метки модели, смена варианта разметки, «старый User-Agent», удаление беседы, правка/удаление сообщений в истории, задержка/обрыв.
- Внесение человеческого сообщения (имитация ручной отправки).
### 5.2 Журнал истины (оракул) [MUST]
Fixture ведёт **собственный серверный журнал** всего, что реально произошло (какие сообщения существуют, когда, от кого, какие переключатели включены). Он недоступен харнессу в ходе прогона и используется только для сверки после него.
### 5.3 Самопроверка
До серии: на нейтральном прогоне журнал истины совпадает с затравкой; каждый переключатель вызывает заданное изменение; отчёт самопроверки входит в паспорт.

## 7. Сценарии
### 7.1 Основная серия (на каждый выбранный хост)
Для каждого вида перезапуска × N=10 × 2 кресла: pre-снимок → перезапуск → post-снимок → вердикт → сверка с журналом истины.
Минимум 2 кресла нужны для T1.4 (два кресла, разные беседы, не склеиваются).
### 7.2 Конкурентный прогон
≥3 одновременно открытых кресла; один перезапуск каждого вида; проверка отсутствия перекрёстного влияния профилей (блокировки профиля, lock-файлы).
### 7.3 Покрытие векторов контракта
Каждый вектор V1–V18 должен быть **вызван** хотя бы раз конкретным переключателем fixture; результат сверяется с таблицей §7 контракта.
| Вектор | Как вызывается (переключатель / условие) |
|---|---|
| V1, V16 | штатный перезапуск; потеря транспорта при живой сессии |
| V2 | отправка, затем `kill`; fixture успевает завершить ответ |
| V3, V4 | истечение сессии; страница challenge |
| V5 | адрес ведёт на другую беседу (подмена `conv_id`) |
| V6 | правка или удаление сообщения внутри префикса |
| V7 | удаление беседы при живой сессии |
| V8 | остановка подгрузки истории |
| V9, V10 | обрыв сразу после отправки; затем длительное ожидание с подтверждением отсутствия |
| V11 | две вкладки/контекста на одну беседу |
| V12, V13 | человеческое сообщение с записью в журнал / без записи |
| V14 | pre по одному пути извлечения, post по другому без пересчёта |
| V15 | смена метки модели |
| V17 | пропуск pre-снимка |
| V18 | искусственное расхождение отпечатков при совпавшей цепочке (дефект снятия снимка имитируется на стороне харнесса) |
### 7.4 Инъекции отказов для ручного fallback (T5)
(1) отключить автоматизацию в середине сценария — человек завершает шаг; (2) оборвать управляющий канал сразу после отправки; (3) принудительный logout; (4) человек отправляет сообщение сам во время паузы. Индикатор режима (`OFF/PAUSED/ACTIVE`) и статус кресла проверяются глазами человека в каждом из четырёх случаев.
### 7.5 Блок M0
Кресла открыты ≥24 ч в режиме без ввода [PARAM: допустимо сократить в пилоте — решение Автора]; рестарты по расписанию; журнал истины подтверждает 0 созданных сообщений.

## 8. Наблюдения и свидетельства
Для каждого прогона: паспорт (ступень, хост, версии браузера/драйвера/ОС, окружение, оператор, ссылка на разрешение, SHA-256 скриптов и конфигурации, версия контракта, [PARAM]); pre/post снимки по §3 контракта; вердикт со списком сработавших правил; запись «намерение → результат»; журнал человеческих действий; журнал истины fixture (после прогона); журнал инцидентов (явное «0», если нет); перечень сырых артефактов и зона хранения; время восстановления (наблюдение, не критерий).
**Классификация вердикта относительно журнала истины:**
`TRUE_RECOVERED` (вердикт RECOVERED, истина — то же) · `FALSE_RECOVERED` (вердикт RECOVERED, истина иная — **критический класс**) · `CORRECT_ALARM` (MISMATCH/AMBIGUOUS/NEEDS_HUMAN/LOST там, где отличие реально) · `FALSE_ALARM` (тревога без реального отличия — допустима, учитывается) · `NO_VERDICT` (вердикт не вычислен — дефект).

## 13. STOP-условия
1. Любое обращение к реальному провайдеру, аккаунту, рабочему профилю браузера, живому чату Коллаборации или `E:\Gemini\AI-Colab\`.
2. Исходящее соединение за пределы loopback.
3. Отправка в режиме M0/M1.
4. `FALSE_RECOVERED` > 0 — серия останавливается для разбора; результат фиксируется.
5. Необходимость выбрать хост, браузер, драйвер или хранилище, чтобы продолжить.
6. Секреты, cookies или токены попали в артефакты, подлежащие передаче.
7. Правка критерия или параметра посреди серии.
8. Для `SNAPSHOT_INCONSISTENT`: см. §9, если мера включена.
