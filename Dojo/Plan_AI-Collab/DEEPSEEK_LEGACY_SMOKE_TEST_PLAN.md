## §1. Цель

Установить фактическое runtime-состояние старого AI-Colab на изолированной копии — без ремонта — и получить достаточное основание для решения о дальнейшей пригодности отдельных механизмов (`RoleBindingManager`, `ProjectContext`, `ChatStorage`, `gemini_cli_executor`, `shared_state`).

**Не входит:** восстановление сервера, устранение F-1…F-27, выбор production-стека, интеграция с AI-Colab 2.

## §2. Фиксация исходного snapshot

- **2.1.** `LEGACY_SNAPSHOT_ID` — конкретный commit/revision HF; если HF не отдаёт commit hash — `snapshot/<commit>` или архив на дату + SHA-256 архива.
- **2.2.** Сверка SHA-256 каждого ключевого файла с паспортами P0.2-A/B/C. Расхождение — `[BLOCKER]`, эксперимент не начинается.
- **2.3.** `requirements.txt` — raw bytes (UTF-16 → decode / hexdump); зафиксировать как `[CODE]`. Задача разработчика, не Автора.
- **2.4.** `git rev-parse HEAD` для E: — через разрешённый маршрут; результат — `E_REVISION` или `[BLOCKER]`.
- **STOP-условие 2:** без `LEGACY_SNAPSHOT_ID` эксперимент не начинается.

## §3. Минимальная среда

- **3.1.** Изолированная копия snapshot в `smoke/`; без пересечения с `E:\Gemini\AI-Colab\` и `projects/*`.
- **3.2.** Отдельная venv (Python 3.11+); зависимости — по `requirements.txt`; если неполон — минимальный набор из фактических импортов; версии — фиксировать.
- **3.3.** `.env` отсутствует. `GEMINI_API_KEY=DUMMY`, `OPENROUTER_API_KEY=DUMMY`; никаких реальных ключей.
- **3.4.** Порт — только `127.0.0.1`, непубличный, отличный от 5000/5005 (например, 5999).
- **3.5.** Сетевой режим: только loopback; исходящие запрещены. `netstat` после запуска; любой внешний коннект — `[BLOCKER]`.

### §4.1. Запуск: какая точка входа реально стартует

- `python start_server.py` — **не запускать как скрипт**; вместо этого: импорт модуля, проверка наличия `clean_python_cache`, `ensure_port_free`, `ensure_project_context`; `ensure_project_context` ожидается падающим на `AttributeError` (F-15). Запуск в ВМ — только если Автор разрешит как отдельный риск.
- `python -m uvicorn app:app --host 127.0.0.1 --port 5999` — проверка, что `app.py` импортируется и отдаёт HTTP.

- `python app2_isolated.py` — стартует ли диагностический вариант.

## §6. Основание для salvage-решения

`RUNTIME_OK` только если:
- **6.1.** Модуль импортируется без ошибок.
- **6.2.** Ключевой метод выполняется на локальных данных без сети и без DUMMY-ключа — или доходит до точки, где DUMMY не нужен.
- **6.3.** Поведение совпадает с `[CODE]`-ожиданием (или расхождение объяснено).
- **6.4.** Нет `[SECURITY FINDING]`.
- **6.5.** Результат повторён минимум в двух независимых запусках на чистой копии.
- **6.6.** Условие запуска записано и привязано к ОС; Linux и Windows — разные статусы.
- **6.7.** Что подменено заглушкой — перечислено.

Иначе — `RUNTIME_FAILED` / `RUNTIME_PARTIAL` / `RUNTIME_OK_AFTER_MODIFICATION` (с diff).

Salvage-решение **не выносится** smoke-тестом; тест даёт **основание** для триады. `[SECURITY FINDING]` — Автору независимо.

## §8. Формат отчёта

```
SNAPSHOT_ID:
  HF_REVISION: <commit|snapshot|sha256>
  E_REVISION:  <commit|UNKNOWN>
  INTEGRITY:   <ok|mismatch(file)>

ENVIRONMENT:
  VENV:        <path>
  DEPS:        <requirements.txt или минимальный набор + версии>
  PORTS:       <listening>
  NETWORK:     <loopback only: Y/N>
  OS:          <Windows/Linux/macOS + версия>
  PYTHON:      <версия>

ENTRY_POINTS:
  - file: <...>  starts: Y/N  level: IMPORTS_OK|APP_STARTS|ROUTE_RESPONDS|FLOW_COMPLETES  port: <...>  routes_alive: [...]  failure: <...>

COMPONENTS:
  - name: <...>  status: RUNTIME_OK|RUNTIME_PARTIAL|RUNTIME_FAILED|RUNTIME_OK_AFTER_MODIFICATION  evidence: <...>  security: <...>  reproduction: <2 независимых запуска Y/N>

FINDINGS:
  - F-<n>: <подтверждён|опровергнут|частично|BLOCKER>  class: [CODE]|[CODE×RUNTIME]

NOT_VERIFIED:
  - <что не проверялось и почему>

STOPPED:
  - <причина или NONE>

SALVAGE_BASIS:
  - <какие кандидаты получили RUNTIME_OK и почему это основание для триады>
```
