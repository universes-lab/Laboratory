## 4. Замечания к `DEEPSEEK_LEGACY_SMOKE_TEST_PLAN` — пересылаются DeepSeek
Содержание плана не правлю. Дополняю фактами, которые у меня есть:
- **app3.py / app2_isolated.py (§4.1).** Замечание верное. Конкретно: по P0.1 `app3.py` запускает `uvicorn.run("app2:app", host, port)` (L730–735), хост и порт берёт из `load_gemini_sockets()["main_server"]` (по умолчанию 127.0.0.1:5005), а не из аргумента командной строки. Значит, «порт 5999» на прямой запуск не распространяется, пока конфигурация не изменена (а изменение = `RUNTIME_OK_AFTER_MODIFICATION`). Предложение: оба файла — только статическая проверка и импорт без `__main__`, как `start_server.py`.
- **Ожидание HTTP 401 (§4.2).** Замечание верное. Дополнительно `[UNKNOWN]`: можно ли направить базовый URL провайдера на локальную заглушку без правки кода (переменная окружения), я не проверял; если нельзя — это модификация.
- **`env -i` (§2.4, §3.2).** Это моя формулировка из рецензии (§2.4) — Unix-идиома; для Windows она неприменима. Принцип остаётся: окружение процесса собирается явно из пустого набора, без унаследованных переменных; способ — решение исполнителя.
- **`netstat` после старта (§5.3).** Согласен с Grok: наблюдение постфактум не запрещает соединение. Запрет должен обеспечиваться средой (правило брандмауэра для интерпретатора либо среда без выхода в сеть), а не проверкой постфактум.
- **Импорт `app` создаёт `GCBEngine` и фоновые объекты.** Подтверждается кодом: все четыре приложения создают `app.gcb = GCBEngine()` при старте (пакет B, заметки). «Только uvicorn» не исключает побочных эффектов; смягчение — пустая очередь GCB в `smoke/` (уже в плане) и отсутствие shell-вызовов.
- **Три написания корня и неизвестная HF-ревизия, `requirements.txt`.** Первое — риск путей, закрывается глоссарием путей (в пакете WS-1a). Второе и третье — известные блокеры исполняемого смоука (не влияют на WS-0/WS-1a). Уточнение: старый сервер у Автора в `E:\Gemini\AI-Colab\`, рабочий каталог — `E:\Gemini\Dojo\AI-Collab\`; в отчёте Grok оба обозначены как `AI-Collab` — это разные папки.
