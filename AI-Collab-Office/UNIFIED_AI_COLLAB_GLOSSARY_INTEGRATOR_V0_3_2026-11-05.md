Вместо молчаливого переопределения предлагаю `AI_INSTANCE_ID` (создание кандидата) и `OCCUPANCY_ID` (активация); `OCCUPANT` — состояние/отношение экземпляра к Office. ## 3. Раздельные состояния

**Статус всегда указывается с типом субъекта и источником решения.** Голый `ACTIVE` недопустим в новых структурированных записях.

| TERM | Значение |
|---|---|
| **OCCUPANT_STATUS** | Например, `ACTIVE / RETIRED / UNAVAILABLE` — точный закрытый перечень уточняет Doctor и утверждает Автор. `ACTIVE` OCCUPANT **не** означает наличие работы. [I/O] |
| **WORK_STATE** | `WAIT` (работы сейчас нет), `ACTIVE` (разрешённое выполнение), `BLOCKED` (конкретное препятствие), `FROZEN` (намеренная остановка), `CLOSED` (формальное прекращение). Применимость к типам объектов и полный closed list ещё требуют утверждения. [I/O] |
| **WORK_PERMIT_STATUS** | `NONE / ACTIVE / REVOKED / EXPIRED` и при необходимости другие отдельные значения; не подменять `WORK_STATE`. [I/O] |
| **PROJECT_STATUS / TRIAD_STATUS** | Статусы проекта или группы отдельно от жизни её участников; замороженная триада сохраняет состав и историю. [S/I] |
| **DOCUMENT_STATUS** | `DRAFT / PROPOSED / ACCEPTED / SUPERSEDED / RETIRED` только по решению уполномоченного владельца/Автору; commit сам по себе статус не меняет. [I/O] |
| **ACTIVE** | Действует **конкретный названный объект** в его собственном классе. [S/I] |
| **WAIT** | Действующий исполнитель не имеет активного предметного задания/допуска; не означает отставки. [S/I] |
| **FROZEN** | Трек или работа сохранены и намеренно остановлены до явного возобновления; не `CLOSED`. [S/I] |
| **BLOCKED** | Продолжение невозможно из-за конкретного `BLOCK_REASON`; желательно фиксировать `UNBLOCK_CONDITION`. [I] |
| **CLOSED** | Формальное завершение процесса, этапа или вопроса; не значит автоматически `ACCEPTED`. [I] |
| **HOLD** | Инструкция не начинать/не продолжать определённый STEP до следующего разрешения; не то же самое, что `DEFER` при архитектурной классификации. [S/I] |

**Примеры:** `OCCUPANT_STATUS: ACTIVE; WORK_STATE: WAIT; CURRENT_TASK: NONE; WORK_PERMIT_STATUS: NONE` — согласованная комбинация. `PROJECT_STATUS: FROZEN` не превращает автоматически OCCUPANT в `RETIRED`.

## 4. Работа и доказательность

| TERM | Определение |
|---|---|
| **EXECUTION** | Фактическое действие: исполнение команды, запуск проверки, отправка сообщения и т. п. Может быть установлено или лишь заявлено; не предполагает принятия. [S/I] |
| **IMPLEMENTATION** | Создание/изменение технической реализации — частный случай EXECUTION. Проверочный запуск сам по себе не implementation. [I] |
| **EVIDENCE** | Проверяемое основание для определённого утверждения, с источником, способом наблюдения и **областью доказательства**. [S/I] |
| **CLAIMED** | Заявлено участником/перевозчиком. Не `VERIFIED`. [S/P] |
| **VERIFIED** | Доказательно подтверждено **в заявленной предметной области** посредством принятого способа. Само слово требует домена/класса. [I] |
| **COMPLETED** | Исполнитель предъявил завершённый им output; не означает внешней приемки. [S/I] |
| **ACCEPTED / ACCEPTANCE** | Уполномоченный проверяющий принял конкретный результат, с указанием субъекта приёмки; не разрешает автоматически следующий шаг. [S/I] |
| **AUTHORIZED** | Уполномоченное решение разрешает будущее действие. [S/I] |
| **EVIDENCE_DOMAIN** | По меньшей мере `TRANSPORT / CLINICAL / DOCUMENT / SCIENTIFIC` как разные системы; окончательный список проектируется. [I/P] |
| **EVIDENCE_GRADE** | Классы внутри одного домена: например, для транспорта `DETERMINISTIC`, `AUTHOR_OBSERVED`, `AGENT_ATTESTED`; для Доктора исторические A–D. Это **не единая шкала**, и `AGENT_ATTESTED` не повышается автоматически до VERIFIED. [P/I] |

**Нормы:** `EXECUTION ≠ EVIDENCE ≠ ACCEPTANCE`; `COMPLETED ≠ ACCEPTED ≠ AUTHORIZED`; `PUBLISHED ≠ CANONICAL`.

**Важная редакционная коллизия `BIRTH`:** Doctor Draft 0.2 говорит о процессе; `DOCTOR_AI_BIRTH_REGISTRY.md` использует `BIRTH` как класс первого назначения. При этом **в истории** буквальное `BIRTH` не переписывать. Полную классификацию birth outcomes утверждает Doctor/Author. [I/O]
