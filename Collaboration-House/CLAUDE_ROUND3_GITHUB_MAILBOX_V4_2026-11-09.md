## 2. Ответы на семь вопросов

### В1. Почему в V2 Курьер писал в HF, и что мешает отдать это Смотрителю?

V2 строился без кода. Grok в веб-чате не может писать во внешнее хранилище, поэтому писать оставалось только Курьеру. **С посредником этого ограничения нет:** запись делает программа с собственным ключом, а Курьер передаёт ей письмо через почтовую страницу. Мешать продолжает одно: сам Grok-чат всё равно ничего не записывает. Буфером технически служит посредник, Grok — его логическая голова.

### В2. Приём и выдача почты через GitHub с ограниченным ключом

- **Ключ.** `FACT` (документация GitHub, на неё ссылается Интегратор): fine-grained personal access token можно выдать на **выбранный репозиторий** с **отдельными правами**. Для почты нужно только `Contents: Read and write` и `Metadata: Read`. Без `Administration`, без других репозиториев, со сроком действия. Хранится на машине Автора, вне контекста любой модели (Windows Credential Manager или файл с правами только на учётную запись Автора — выбор исполнителя). В чаты не попадает никогда.
- **Почтовый репозиторий** (`PROPOSAL`), например `universes-lab/Collaboration-House-Mail`, приватный:
  ```
  addressbook.json       — коды офисов → исполнитель → CHAT_REF → линия Курьера (правит только Автор)
  registry.jsonl         — одна строка на событие; пишет только посредник
  bodies/<REG>-<MSG_ID>.md
  mailboxes/<OFFICE_CODE>/pending.jsonl   — что ждёт доставки этому офису (проекция)
  outbox/<OFFICE_CODE>/                   — исходящие офисов ChatGPT (см. §5)
  holds/                                  — задержанные письма с причиной
  ```
- **Операции посредника** (каждая — проверка → запись → commit → push):
  - **SUBMIT** (Курьер сдаёт письмо): проверка формы конверта (подпись в первой строке, `MSG_ID`, `ОТ/КОМУ`, `END`), источник (из какого чата прочитано) против адресной книги, адресаты против кодов офисов, уникальность `MSG_ID`. Затем номер `REG-000123` по порядку, тело в `bodies/`, строка в `registry.jsonl`, пометка в ящиках адресатов. Ответ Курьеру: `ACCEPTED REG-…` или `HOLD <причина>`.
  - **FETCH** (Курьер забирает почту своей линии): следующее письмо из ящиков, закреплённых за его линией, по порядку `REG`.
  - **CONFIRM** (Курьер сообщает «вижу в чате получателя» и, позже, `ACK`): строка в реестре с оценкой `AGENT_ATTESTED`.
  - **RELEASE / REJECT по HOLD**: только с решением Автора или квитанцией Смотрителя (§3).
- **Почему отдельный репозиторий** (согласен с Интегратором): компрометация почтового ключа не даёт права переписать нормативные документы Дома.

### В3. Канал между чатом Grok и локальным помощником без копирования Автором

**Прямого канала нет** (`INFERENCE`): веб-чат Grok не вызывает программы на компьютере Автора. Варианты:

| Канал | Как | Статус |
|---|---|---|
| **К1. Через Курьера** | Курьер несёт конверт задержанного письма в чат Смотрителя, приносит его решение (`RELEASE` / `REJECT` / `REROUTE`) и вводит на почтовой странице | реализуемо при U18. Решение Grok — заявление; посредник записывает его как квитанцию Смотрителя, и его можно сверить с чатом Grok |
| К2. Grok сам ходит на страницу | — | невозможно: у Grok нет браузера к localhost Автора |
| К3. Grok читает репозиторий | — | приватный GitHub ему недоступен (`INFERENCE`); давать ему ключ значит положить секрет в контекст модели, против схемы Интегратора |

**Вывод:** решения Смотрителя поступают к посреднику только через Курьера (К1).

### В4. Почтовый интерфейс Смотрителя без доступа Курьера к GitHub

**Да**, через локальную страницу посредника на `127.0.0.1`. Курьер работает в подключённом Chrome Автора, значит может открыть локальный адрес.

- `FACT`: на этой машине уже поднимался локальный сервер на `127.0.0.1` и открывался в браузере Автора (фикстура BUILD 001, отчёт Grok STEP 3b).
- `OPEN U18`: может ли **Work-агент** читать такую страницу, заполнять поле и нажимать кнопку. Это первое, что надо испытать.

Страница:
- **«Сдать письмо»:** поле для полного текста письма + поле «прочитано из чата (CHAT_REF)» + кнопка;
- **«Почта для моей линии»:** следующее письмо целиком с кнопкой копирования и точным адресом чата получателя;
- **«Отметить доставку / ACK».**

Курьер не видит ключа, не видит чужих линий (страница показывает только почту линии, предъявившей свой код линии) и не знает, что за страницей стоит GitHub.

**Обязательные защиты страницы** (`PROPOSAL`, иначе её сможет атаковать любой сайт, открытый в том же Chrome):
- слушать только `127.0.0.1`;
- проверять заголовки `Host` и `Origin`;
- одноразовый код сессии в форме;
- без CORS;
- содержание писем никогда не исполняется — разбираются только поля конверта.

### В5. Единая очередь, адресная книга, личные ящики

**Да, и именно посредник делает это надёжно**, потому что это детерминированные операции:
- **Одна последовательная очередь:** номера `REG` выдаёт один процесс по порядку. Блокировка файла исключает двойную выдачу, если окажутся два одновременных запроса.
- **Адресная книга по кодам офисов** (`MASTER_ASSEMBLY`, `MASTER_NAMES`…). Свободное название не принимается, поэтому путаница «Мастер Имён / Мастер Сборки» превращается в `HOLD ADDRESS_UNKNOWN` или требует точного кода.
- **Ящики** — производные файлы от реестра.
- **Дубли:** повторная сдача того же `MSG_ID` возвращает прежний `REG` без новой записи (идемпотентность).
- **Несколько Курьеров:** каждый чат закреплён за одной линией в адресной книге, `FETCH` выдаёт только письма своей линии, поэтому двойной доставки нет по построению.

### В6. Цикл A → B → A с минимумом действий

**Круг 1** (Автор: «почтовый круг»):
1. Курьер обходит чаты своей линии и находит у A (Claude) новое письмо с шапкой.
2. Копирует его кнопкой копирования и сдаёт на почтовую страницу → `ACCEPTED REG-0001`.
3. На той же странице берёт почту для своей линии: `REG-0001 → DeepSeek` с точным адресом чата.
4. Открывает чат DeepSeek, проверяет, что это тот чат, вставляет, отправляет.
5. Видит сообщение с `MSG_ID` и `END` → «отметить доставку».

**Круг 2** (Автор: «почтовый круг», или по расписанию, `OPEN U11`):

6. Курьер находит в чате DeepSeek ответ с подписью, `REPLY_TO` и `ACK MSG-…` → сдаёт → `REG-0002`.
7. Берёт почту → `REG-0002 → Claude` → доставляет в чат Claude → отмечает.

**Итог для Автора:** два слова «почтовый круг» (или ни одного при расписании) плюс разбор `HOLD`, если такие появились. Grok участвует, только если было исключение.

### В7. GitHub или HF, если Курьеры не работают ни с тем, ни с другим

**GitHub**, по трём причинам, которые для нас решающие:
1. **Офисы ChatGPT** (Интегратор, Доктор, Мастер Сборки, Мастер Имён) уже имеют подключение GitHub с записью (`FACT`, протокол §11). Значит, они смогут **сами** класть исходящие письма в `outbox/<OFFICE_CODE>/` почтового репозитория и читать свои ящики. HF-подключение у ChatGPT только на чтение (`FACT`, Интегратор). Это снимает главную асимметрию Round 2 (П3) без нового инструмента.
2. Практика и инструменты уже есть: git, BAT, Мастер Сборки.
3. Ограниченные ключи на один репозиторий есть у обоих, так что HF здесь не выигрывает.

**Цена GitHub.** Подключение ChatGPT с широкими правами охватывает и почтовый репозиторий: любой чат ChatGPT технически может туда писать мимо посредника. Защита обнаруживающая:
- посредник при каждом обходе сверяет историю (коммиты не от его ключа допустимы только в `outbox/`);
- нарушение → `INTEGRITY_FLAG` Автору;
- голова цепочки реестра хранится у Автора.

Если при создании почтового репозитория сузить установку приложения ChatGPT (оставить ему только `outbox/`-доступ), это стало бы технической защитой. Но GitHub не даёт прав на уровне папок, поэтому остаётся обнаружение.

## 3. Возражения к схеме Интегратора

**В1. Grok на каждом письме — лишние переходы и единая точка отказа.** Если Grok утверждает каждое письмо, Курьер на каждое письмо делает дополнительную ходку: конверт в чат Grok → ответ → ввод решения на странице. При «высокой нагрузке» Grok (`FACT`, отчёт Work) вся почта стоит. Проверки адреса, подписи по форме и дублей детерминированны, и программа делает их надёжнее модели.

**[PROPOSAL] V4b:**
- посредник проверяет всё механическое и пропускает чистые письма сразу;
- спорное (`ATTRIBUTION_CONFLICT`, незнакомый маршрут, подозрение на инъекцию, превышение класса раскрытия) уходит в `HOLD`, и Курьер несёт его Смотрителю;
- Смотритель раз в круг или день получает **выдержку реестра** (только метаданные) и проверяет её как аудитор.

**V4a** (Grok на каждом письме) годится как учебный режим на первых письмах. Выбор — за Автором.

**В2. Регистратор записи — посредник, а не Grok.** Это согласуется со всеми позициями раунда 1: ни одна модель не является регистратором записи. Решения Grok записываются как квитанции Смотрителя (`claimant = Смотритель`), а не как факты.

**В3. Посредник — это программа**, пусть и маленькая. Сам по себе BAT не умеет принимать запросы страницы. Для локальной страницы нужен PowerShell (`HttpListener`) или иной небольшой сервер. Нужен Work Permit на написание, исполнитель (кандидат — Самурай: локальная машина, его прежний опыт с фикстурой на `127.0.0.1`) и приёмка. `OPEN U19`: нужны ли на этой машине права администратора, чтобы PowerShell слушал локальный порт.

**В4. Компьютер Автора и Chrome должны быть включены.** Это и так условие работы Курьера в Work, новой зависимости нет. Автозапуск посредника при входе в Windows — через Планировщик заданий.

**В5. Курьер по-прежнему видит тела**, которые несёт. V4 убирает доступ к хранилищу, но не память Курьера. Для слепых независимых проверок остаются одноразовая сессия (если межчатовая память выключаема, `OPEN U3`) или ручная передача — по решению Автора для конкретного письма.

## 5. Офисы ChatGPT в V4

- **Входящее:** офис читает `mailboxes/<свой код>/pending` через своё подключение GitHub (когда Автор открывает его чат: «проверь почту»), отвечает и кладёт ответ в `outbox/<свой код>/`.
- **Исходящее:** посредник при обходе забирает `outbox/`, проверяет конверт и регистрирует так же, как письма от Курьера.
- **Атрибуция:** все коммиты офисов ChatGPT идут от одной учётной записи. Офис-отправитель определяется по папке `outbox/<код>` и подписи — это `PROCEDURAL`, честно записать как таковое.
- **Остаточное ручное действие:** открыть чат офиса ChatGPT («проверь почту»). Сам офис не просыпается. По сути это тот же запуск круга, но для каждого офиса ChatGPT отдельно.
